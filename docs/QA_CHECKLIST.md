# Phase 1 QA Checklist

目標：驗證 300 道三語食譜在 GitHub Pages、iPad 橫向及手機直向可可靠使用。  
測試符號：`[ ]` 未測、`[x]` 通過；每個失敗項需附裝置／瀏覽器、重現步驟、截圖及 recipe ID。

## 1. 發布門檻

- [ ] 正式資料剛好 300 道，所有 `recipe.id` 唯一且穩定。
- [ ] 菜系數量符合 `RECIPE_GUIDELINES.md` 的 300 道分布。
- [ ] 至少 90 道為原生蛋奶素；其餘含動物來源的食譜都有完整蛋奶素版本。
- [ ] 所有菜式三語標題、簡介、材料、步驟、安全提示及圖片替代文字齊全。
- [ ] 每道菜有完成圖，每一步有正確對應圖片。
- [ ] 每張外部圖片有來源及可再使用授權；生成圖有生成記錄。
- [ ] 生產 build 無 error、broken route、missing asset 或 console error。
- [ ] GitHub Pages 以專案子路徑開啟正常，重新整理深層食譜 URL 不會 404。
- [ ] 所有功能在離線／靜態託管限制下不依賴私密 API key。

## 2. 自動資料完整性

對全部 300 道菜執行：

- [ ] 必填欄存在，型別正確，時間和數量是合理的有限正數。
- [ ] `prepMinutes + cookMinutes` 與 `totalMinutes` 一致或有明確並行時間說明。
- [ ] 每個材料都有三語名稱、數值、單位和 `ingredientId`。
- [ ] 每個必要材料至少被一個步驟引用；步驟沒有引用不存在的材料。
- [ ] 份量縮放後數值不出現 `NaN`、負數、0 或不合理小數。
- [ ] 每個步驟有三語文字、圖片、三語 `alt`，步驟編號連續。
- [ ] 三語版本中的數量、時間、溫度和次序完全一致。
- [ ] 每個 tag 使用受控 `tagId`，有三語名稱；沒有只因大小寫或拼法不同而重複的 tag。
- [ ] 致敏原由一般版和蛋奶素版各自計算，與材料標註一致。
- [ ] 每個圖片路徑可讀、尺寸存在且沒有 404。
- [ ] 所有內部 recipe link 指向存在的 ID。

建議加入 schema 驗證、孤立資產檢查、重複內容相似度報告及三語數值 diff，並在 CI 阻止失敗資料發布。

## 3. Responsive Layout

最低實機／模擬 viewport：

| 類型 | Viewport |
|---|---|
| 小型手機直向 | 320 × 568 |
| 常見手機直向 | 390 × 844 |
| 大型手機直向 | 430 × 932 |
| iPad 橫向 | 1024 × 768 |
| iPad Pro 橫向 | 1366 × 1024 |
| 桌面 | 1440 × 900 |

每個 viewport 均測：

- [ ] 沒有水平捲動、文字截斷、卡片重疊或內容超出畫面。
- [ ] Header、搜尋、語言選擇、素食切換和返回操作可見且可操作。
- [ ] 觸控目標至少約 44 × 44 CSS px，目標之間有足夠間距。
- [ ] 手機直向單欄閱讀順序合理；材料和步驟不被雙欄壓窄。
- [ ] iPad 橫向有效使用寬度，可用材料／步驟雙欄或固定目錄，但不遮住內容。
- [ ] 圖片保持比例、不拉伸；延遲載入時保留空間，沒有明顯 layout shift。
- [ ] 長英文／印尼文標題、200% 字體縮放及長材料名稱不破版。
- [ ] 軟鍵盤打開時搜尋欄和結果仍可使用。
- [ ] 直向／橫向旋轉後保留語言、搜尋、篩選、素食模式及目前食譜位置。
- [ ] iOS Safari safe area、瀏海和底部工具列不遮擋固定元件。
- [ ] hover 不是唯一顯示重要資訊或操作的方法。

瀏覽器最低測試：iOS/iPadOS Safari、Android Chrome、桌面 Chrome、Safari、Firefox、Edge 的目前及上一主要版本。

## 4. 三語及對照顯示

針對每種單語和每個雙語組合測試：

- [ ] 單語：繁中、英文、印尼文。
- [ ] 雙語：繁中＋英文、繁中＋印尼文、英文＋印尼文。
- [ ] 使用者不能選擇兩次同一語言；主／副語言可互換。
- [ ] 切換語言即時更新導航、按鈕、搜尋提示、tag、材料、步驟、警告及空狀態。
- [ ] 雙語顯示有清楚的主次層級，但兩種語言完整，不只翻譯標題。
- [ ] 語言切換不重設素食模式、搜尋、份量、完成紀錄或目前捲動位置。
- [ ] 重新整理及重開頁面後保留語言選擇。
- [ ] 不支援／損壞的語言值安全回退到預設語言，不顯示 raw key。
- [ ] `<html lang>` 與單語主語言一致；雙語區塊使用正確局部 `lang`。
- [ ] 以 30 道分層樣本人工核對三語語意；數字、單位、火力、食安警告零差異。
- [ ] 印尼文由熟悉家庭烹調詞彙的人覆核，不以機器直譯直接發布。
- [ ] 繁中採香港用字；關鍵食材同時可被中國大陸／台灣常見別名搜尋。

## 5. 搜尋與 Tag

### 5.1 基本搜尋

- [ ] 可用三種語言搜尋菜名、主要材料、成分、菜系、烹調法及 tag。
- [ ] 混合語言查詢可用，例如 `chicken 蒸`、`豆腐 pedas`。
- [ ] 大小寫、前後空白、重複空白和常見標點不影響結果。
- [ ] 香港同義詞能命中同一資料：粟米／玉米、薯仔／馬鈴薯、番茄／蕃茄等。
- [ ] 精確菜名或主要材料優先於簡介中偶然出現的字詞。
- [ ] 空查詢顯示全部；零結果有三語提示、清除條件操作和可行建議。
- [ ] 輸入特殊字元、emoji、超長字串不會崩潰或注入 HTML。
- [ ] 300 道資料上輸入後結果在一般手機達到可感知即時（目標 <100 ms 計算，不含首次載入）。

### 5.2 篩選邏輯

- [ ] 可按菜系、食材、成分、烹調法、難度、時間、辣度、餐別、蛋奶素篩選。
- [ ] 同類別多選採 OR；不同類別採 AND，畫面有清楚說明。
- [ ] 結果數、active chips 和實際結果一致。
- [ ] 可逐一移除 chip 及一鍵清除全部。
- [ ] 瀏覽器返回／前進正確還原查詢和篩選；如以 URL 保存，分享 URL 可重現結果。
- [ ] 素食模式開啟時，不出現無可用蛋奶素版本的結果，材料 tag 依蛋奶素版本更新。
- [ ] 致敏原排除不被「可轉蛋奶素」誤當作無致敏原保證。

## 6. 食譜詳情與烹調可用性

- [ ] 首屏看見菜名、完成圖、總時間、份量、難度、辣度、菜系和蛋奶素狀態。
- [ ] 材料按主料、醃料、調味、芡汁／伴碟分組。
- [ ] 每項材料有精確數量、單位、備料方式及必要替代。
- [ ] 調整份量同步更新一般版和蛋奶素版材料，不改變文字中的固定安全溫度。
- [ ] 步驟順序明確，每步顯示材料用量、火力、時間和完成提示。
- [ ] 技法術語有解釋；沒有「煮至熟」、「適量」等無量化關鍵指示。
- [ ] 計時器如有提供，可同時處理多個時間且在鎖屏／切頁後合理恢復。
- [ ] 每步圖片與文字一致，放大後仍清晰，失敗時有不妨礙閱讀的 fallback。
- [ ] 重要食安警告出現在相關步驟，而非只在頁尾。
- [ ] 以英文及印尼文各進行至少 5 道新手實煮測試，使用者毋須口頭追問。

## 7. 蛋奶素模式

為每一個替換類型至少抽測 3 道；高風險隱藏成分全部 100% 測試。

- [ ] 介面明示「蛋奶素：包括蛋和奶，不包括肉、家禽、魚、海鮮及動物湯底」。
- [ ] 切換後材料、數量、步驟、圖片、時間、tag、致敏原和購物資料一同改變。
- [ ] 往返切換 10 次資料仍一致，不出現重複材料或累積縮放誤差。
- [ ] 蠔油、魚露、蝦醬、蝦米、雞粉、肉湯、喼汁、明膠、豬油等隱藏動物來源全被處理。
- [ ] 蛋奶素版不存在肉、禽、魚、海鮮、動物脂肪或動物湯底的文字、tag 或圖片。
- [ ] 替換後步驟使用正確火力、時間和熟度提示，不保留「肉汁清澈」等不適用文字。
- [ ] 新增的大豆、麩質、蛋、奶、堅果等致敏原立即顯示。
- [ ] 植物肉不默認為低鈉或無致敏原；頁面提示查看包裝標籤。
- [ ] 切換後份量縮放、搜尋和完成紀錄仍以同一 recipe ID 正常運作。
- [ ] 原生蛋奶素菜式不顯示虛假的「已替換肉類」內容。
- [ ] 模式狀態重新整理及重開頁面後保留。
- [ ] 模式開啟不構成嚴重過敏安全承諾，相關免責提示可被讀屏器讀到。

## 8. 烹調紀錄與 localStorage

建議紀錄包含 `recipeId`、完成時間（ISO 8601）、模式、份量、可選評分／備註及 schema version；避免儲存不必要個人資料。

- [ ] 「已煮」操作一次只新增一筆；快速連按不意外重複。
- [ ] 同一道菜可在不同日期記錄多次，歷史按時間正確排序。
- [ ] 記錄顯示當時的一般／蛋奶素模式及份量。
- [ ] 重新整理、關閉分頁及重新開啟瀏覽器後資料仍存在。
- [ ] 多分頁同時新增不會靜默覆蓋另一分頁資料；必要時監聽 `storage` 事件。
- [ ] 可刪除單筆紀錄，並有確認或可復原操作。
- [ ] 清除全部紀錄要明確二次確認，只刪除本 app 的 key。
- [ ] localStorage 被禁用、quota exceeded 或讀寫拋錯時，app 仍可瀏覽食譜並顯示友善三語提示。
- [ ] 空值、截斷 JSON、錯誤型別、未知 schema version 不令 app 白屏；安全回復／遷移並保留可救資料。
- [ ] app 更新、recipe 改名或排序後，舊 `recipeId` 紀錄仍正確關聯。
- [ ] 不把 UI 語言顯示字串當 ID 儲存。
- [ ] 如提供匯出／匯入，錯誤檔案不能執行程式碼；匯入前預覽及確認。
- [ ] 無痕模式和使用者清除網站資料後紀錄消失的限制，在說明中交代。

## 9. 食物安全與內容 QA

對所有涉及項目做自動搜尋及人工覆核：

- [ ] 肉、家禽、蛋和翻熱步驟有 75°C／30 秒或等效且合適的安全指示。
- [ ] 湯羹／炆燉有煮滾至少 1 分鐘指示。
- [ ] 非全熟蛋只建議使用巴士德消毒蛋。
- [ ] 解凍指示只採雪櫃、微波或流動自來水安全方法；微波／流水解凍後立即烹煮。
- [ ] 剩菜有 2 小時內冷藏、只翻熱一次的提示。
- [ ] 生熟食物分開、手部與溫度計清潔提示在適用位置。
- [ ] 油炸、蒸氣、刀、攪拌機、焗爐及壓力煲有具體風險提示。
- [ ] 致敏原與材料、醬料隱藏成分和素食替代一致。
- [ ] 未經營養計算的菜式不顯示「低鈉」、「高蛋白」等定量健康聲稱。

## 10. Accessibility

- [ ] 所有功能可只用鍵盤完成；焦點順序與畫面閱讀順序一致。
- [ ] 焦點指示清楚，dialog 開關時焦點正確移入及返回。
- [ ] 語言、素食和 filter controls 有可理解的 accessible name、role、state。
- [ ] 搜尋結果數及「已記錄」狀態透過適度的 live region 宣告，不造成重複轟炸。
- [ ] 圖片有相應語言的描述性 alt；純裝飾圖 alt 為空。
- [ ] 標題層級連續；材料列表和步驟使用語義化 list。
- [ ] 文字和互動元件符合 WCAG AA 色彩對比；資訊不只靠顏色表達。
- [ ] 200% zoom、文字放大及 prefers-reduced-motion 下仍可完整使用。
- [ ] 自動動畫可停止；不使用閃爍內容。
- [ ] 以 VoiceOver（iOS/iPadOS）及至少一款桌面 screen reader 完成：搜尋 → 開啟食譜 → 切語言 → 切素食 → 記錄已煮。

## 11. 效能、PWA 與靜態託管

- [ ] 首頁不預載 300 道的所有步驟大圖；縮圖與詳情圖按需載入。
- [ ] 圖片具有 `srcset`／`sizes`、固定尺寸及現代壓縮格式。
- [ ] 低速 4G 下首頁可先閱讀和搜尋，不因圖片阻塞主要 UI。
- [ ] Lighthouse 行動裝置目標：Performance ≥ 85、Accessibility ≥ 95、Best Practices ≥ 90、SEO ≥ 90。
- [ ] Core Web Vitals 目標：LCP ≤ 2.5 s、CLS ≤ 0.1、INP ≤ 200 ms（以可取得的實機資料為準）。
- [ ] JavaScript 關鍵 chunk、300 道資料和圖片各有合理 cache 策略；新版本不會混用舊 schema。
- [ ] 如支援離線，首次載入後可開啟已快取食譜；未快取圖片有 fallback；更新提示不丟失 localStorage。
- [ ] GitHub Pages base path、asset path、manifest、service worker scope 在專案網站和 custom domain（如有）均正確。

## 12. Browser 視覺驗證腳本

Browser 驗證需在實際 production build（而非只在開發伺服器）執行並保存截圖：

1. 開啟首頁，分別截取 390 × 844、1024 × 768、1366 × 1024。
2. 搜尋 `粟米`、`chicken`、`tempeh`，核對結果及跨語別名。
3. 同時選「廣東」「30 分鐘」「可轉蛋奶素」，核對 AND／OR 行為。
4. 開啟一道人氣葷菜，分別截取單語、繁中＋英文、英文＋印尼文。
5. 開啟蛋奶素模式，逐項比較材料、步驟、圖片、tag、致敏原和時間。
6. 確認新開食譜預設 3 人，再改為 1、2、4、6 人，核對小數、單位及不可分割材料。
7. 記錄「已煮」，重新整理、關閉再開啟，核對 localStorage 歷史。
8. 模擬 localStorage 損壞／不可用，確認不白屏。
9. 以鍵盤及讀屏走完整核心流程。
10. 檢查 network、console、broken images、404、layout shift 和可點擊區域。

## 13. MX2-TT20SC、份量及圖片專項

以下規格由本專案保存的官方文件
`tmp/pdfs/mx2-manual.txt`、`tmp/pdfs/mx2-cookbook.txt` 及其渲染頁核對。
涉及 MX2 的食譜必須將「模式、功率／溫度、時間、預熱、水箱、器皿、配件及層位」
作為結構化資料顯示，不能只寫「放入焗爐煮熟」。

### 13.1 MX2 硬性操作範圍

| 功能 | 官方可選範圍／要求 |
|---|---|
| 快速烹調 | 600W、初始 30 秒；時間最多 90 分鐘。 |
| 微波 | 800／600／500／200／100W；時間最多 90 分鐘。 |
| 純蒸 | 50–100°C；時間最多 90 分鐘；開始前清潔淨水箱並加入過濾水／蒸餾水。爐腔過熱可能顯示 `F-01`。 |
| 高溫蒸 | 110–130°C；時間最多 90 分鐘；水箱要求同純蒸。 |
| 蒸氣烤焗 | 100–230°C，有預熱及無預熱兩種；時間最多 90 分鐘；必須加水。預熱完成蜂鳴後才放食物。 |
| 烤焗 | 70–230°C，有預熱及無預熱兩種；時間最多 90 分鐘。 |
| 發酵 | 28–45°C；1 分鐘至 12 小時；爐腔過熱可能顯示 `F-01`。 |
| 保溫 | 60°C；1 分鐘至 2 小時。 |
| 消毒／自清潔 | 蒸氣功能；消毒 15–30 分鐘、自清潔 10 分鐘；先清潔水箱並加過濾水／蒸餾水。 |

水箱測試：

- [ ] 純蒸、高溫蒸、蒸氣烤焗及蒸氣清潔步驟均明示先把淨水箱加滿 `<40°C` 過濾水／蒸餾水。
- [ ] 顯示「需加水」時有安全提示；完成後倒掉淨水箱餘水及污水箱積水。
- [ ] 非蒸氣模式不誤導使用者加水；蒸氣模式不漏掉水箱步驟。

器皿、配件與層位測試：

- [ ] 微波及任何包含微波的組合模式，只使用標明微波安全、無裂紋、無金屬裝飾的耐熱玻璃／陶瓷／合適塑膠；蓋子留孔排氣。
- [ ] 微波模式不使用鋁盤、金屬或金屬裝飾器皿、金屬手柄紙盒、金屬紮帶、紙袋、發泡膠或木器。
- [ ] 原廠烤盤及烤架不在微波模式使用；微波容器直接放爐腔平板。
- [ ] 金屬烤盤、烤架、錫紙只在官方容許的純蒸／烤焗／蒸氣烤焗步驟出現；組合模式含微波時仍禁用。
- [ ] 純蒸食譜一般為耐熱碟／碗放蒸烤架、置下層；蒸氣烤焗一般為烤盤置下層。
- [ ] 菜單 17 烤番薯使用烤盤＋上層；菜單 22 戚風蛋糕使用 8 吋模、蒸烤架凸起向上並放爐腔平板；不可一律寫「中層」。
- [ ] 需要接滴漏食物時用烤盤；每道 MX2 食譜逐項核對官方層位，不以一般焗爐慣例推測。
- [ ] 不確定器皿只可依說明書做 250ml 冷水並排測試：最大功率 1 分鐘；空器皿變熱便不可用。
